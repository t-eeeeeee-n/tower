# Tower

複数のコーディングエージェント（Claude Code / Codex / GitHub Copilot CLI / Antigravity CLI）のセッションを 1 つのウィンドウで並列に管理する Windows 用デスクトップアプリです。
左のサイドバーで各セッションの状態（作業中・入力待ち・完了）とメモリ使用量を確認し、右のターミナルで操作します。

## 必要なもの

1. **Rust**（1.90 以上）: https://rustup.rs からインストールし、`rustup default stable-msvc` を実行
2. **Visual Studio Build Tools**: 「C++ によるデスクトップ開発」ワークロードを選択してインストール
3. **Node.js** 20 以上
4. **Git for Windows**（Git Bash）
5. 使いたいエージェント（Git Bash から起動できる状態）

| エージェント | コマンド | 状態の取り方 |
| --- | --- | --- |
| Claude Code | `claude` | hooks |
| Codex | `codex` | hooks（初回だけ Codex の画面で信頼の承認が必要） |
| GitHub Copilot CLI | `copilot`（1.0 以降） | hooks |
| Antigravity CLI | `agy` | 画面の様子から推測（部分対応） |

WebView2 は Windows 10/11 に標準で入っています。

## 起動

```bash
npm install
npm run tauri dev
```

初回は Rust の依存ビルドに数分かかります。

## 配布用ビルド

```bash
npm run tauri build
```

`src-tauri/target/release/bundle/nsis/` にインストーラ（.exe）、`bundle/msi/` に MSI ができます。
インストールせずに使うなら `src-tauri/target/release/tower.exe` を直接起動しても動きます。

### リリース（GitHub Actions）

`package.json`・`src-tauri/tauri.conf.json`・`src-tauri/Cargo.toml` の version を揃えて上げ、同じ番号のタグを push すると、GitHub Actions がテストしてからインストーラを作り、リリースとして公開します（`.github/workflows/release.yml`）。タグと version が違うときや、テストが通らないときは止まります。

```bash
git tag v0.2.0
git push origin v0.2.0
```

コード署名はしていないので、配ったインストーラは初回に Windows の SmartScreen に警告されます。

## 使い方

「＋」またはCtrl+Shift+Nでフォルダと起動するエージェントを選ぶと、そのフォルダで Git Bash が起動し、続けてエージェントが立ち上がります。

エージェントはボタンで選びます（←→キーでも選べます）。初回は何も選ばれていないので自分で選び、2 回目以降は前回選んだものが選ばれた状態で開きます。PATH に見つからないエージェントは「未インストール」と表示され、選べません。エージェントを自分で `claude` などと打って起動すると状態が表示されないので、使うエージェントはここで選んでください。

| キー | 動作 |
| --- | --- |
| Ctrl+Shift+N | 新しいセッション |
| Ctrl+0 | 一覧画面 / 直前のセッションへ切り替え |
| Ctrl+1〜9 | サイドバーの番号のセッションへ切り替え |
| Ctrl+Shift+A | 次の入力待ちセッションへ移動 |
| Ctrl+Shift+E | ファイルの表示 / 非表示 |
| Ctrl+Shift+L | ターミナル / 会話の切り替え |
| Ctrl+Shift+B | サイドバーをたたむ / 開く |
| Shift+Enter / Alt+Enter | エージェントの入力欄で改行（どちらも同じ信号を送る。bash では何もしない） |
| Ctrl+Shift+C / V | コピー / 貼り付け（Ctrl+C はエージェントの中断に使うため） |
| Ctrl+Shift+W | 表示中のセッションを閉じる |
| Ctrl+Shift+T | 指示のテンプレートを入れる |
| Ctrl+, | 設定（配色・フォント・カーソル・通知） |
| F1 | ショートカットの一覧（サイドバーの上の「?」でも開けます） |

ヘッダーの「ファイル」または Ctrl+Shift+E で、ターミナルの右にセッションのフォルダのファイルを表示します（見るだけで、編集はできません）。Git で変更されたファイルには印（M 変更・A 追加・D 削除・R 名前の変更・U Git 管理外）が付き、.gitignore などで Git の対象から外れているファイルは薄く表示します（.gitignore は Tower が読むだけで、git は呼びません）。変更されたファイルは、選ぶと変更前との差分を表示します。「全体」に切り替えるとファイル全体を表示し、Markdown（.md）は「プレビュー」で整形して表示します（スクリプトやスタイル、外部の画像は取り除きます。Web のページへのリンクは既定のブラウザで開きます）。「変更のみ」にすると変更されたファイルだけに絞れます。一覧と Git の変更は、エージェントの状態が変わったとき・Tower のウィンドウに戻ったとき・↻ を押したときに更新します。開いているファイルの中身は、表示中は数秒ごとに読み直します（差分の表示は一覧と同じときに更新します）。境目をドラッグすると幅を変えられます。セッションのフォルダの外のファイルは開けません。

Claude Code と Codex のセッションでは、ヘッダーの「会話」または Ctrl+Shift+L で、ターミナルの場所を会話の表示に切り替えられます。会話の記録（Claude Code は `~/.claude/projects`、Codex は `~/.codex/sessions` の JSONL）を読みやすく整えたものです。自分の発言と返事は大きめの文字で、ツールの呼び出しは時系列の線の上に 1 行ずつ（何をしたか・対象・結果の要約。例：「読む README.md 30 行」「変更 login.css +2 −1」）並べ、クリックすると結果を開きます。上には最後の依頼の要約（エージェント・かかった時間・ツールの数・変更したファイル・実行中のもの）を出し、返事の前にはエージェントの名前を出します。エージェントの名前は、ヘッダー・サイドバー・カードでもエージェントごとの色で出します。作業中は、エージェントの画面に出ている作業中の行（「✻ Thinking… (12s)」など）を入力欄の上に出します。貼り付けた画像や、エージェントが読んだ画像（スクリーンショットなど）は縮小して表示し、クリックすると大きく表示します（PNG・JPEG・GIF・WebP で、base64 で 4 MB までのもの）。作業中は、結果がまだ届いていないツール（実行中の Bash やサブエージェントなど）に「実行中」と経過時間を出します。Claude Code のサブエージェントの会話も読めます。会話の上の列の「サブエージェント」を押すと一覧が開き、選ぶとその会話を表示します。Agent ツールの行の「会話を見る」でも開けます。記録ファイルが 15 秒以内に書き換えられたものを「動いている」とみなし、ボタンに「動いている数/全部の数」を出します。同じ列の「シェル」では、Claude Code が裏で動かしているシェル（Bash の run_in_background）を選べ、出力の末尾（64 KB まで）を表示します。一覧には、実行中なら経過時間、終わっていれば「完了」「失敗」「停止」を出します。Claude Code が終わると、終わった知らせが記録に無いシェルも「停止」とみなします。サブエージェントやシェルには直接指示を送れないので、見ている間は入力欄を使えません。文字を打つかファイルを入れるとメインに戻ります。この切り替えは一覧のカードでも使えます。会話・ターミナル・一覧のカードの画面に出た Web のページ（http/https）の URL は、押すと既定のブラウザで開きます（それ以外の種類のリンクは開きません）。入力欄の下には、Claude Code が入力欄の下に出している行（ステータスラインや auto mode などのモード）を画面から拾って出します。許可の確認や選択肢はターミナルにしか出ないので、入力待ちになると自動でターミナルに戻り、作業が再開すると会話の表示に戻ります。下の入力欄から指示を送れます（Enter で送信、Shift+Enter か Alt+Enter で改行、作業中は Esc で中断）。送れるのは指示待ちのときだけで、作業中に書いた指示は終わってから送ります。作業中は許可の確認が画面に出ていることがあり、そこに文字を送ると答えとして扱われるためです。ファイルのドロップや貼り付けた画像の場所は、この入力欄に入ります。入力欄が空のときに「/」を打つと、コマンドの候補を選べるようターミナルに切り替わり、そこから先はターミナルで打ちます（作業が始まるか Ctrl+Shift+L で会話の表示に戻ります）。記録ファイルの場所は SessionStart の hook で受け取るので、Tower から起動したセッションだけが対象です。記録の形式は公開された仕様ではないため、エージェントの更新で表示が崩れることがあります。

Git の変更の表示は、フォルダごとに最初の 1 回だけ「このフォルダを信頼して表示する」で許可が必要です。Git はリポジトリの設定によってコマンドを実行することがあるので、許可していないフォルダでは Tower は git を呼びません（ファイルの一覧と中身は許可しなくても見られます）。信頼したフォルダから作った worktree は最初から許可済みになります。許可したフォルダは `%APPDATA%\dev.tower.app\trusted-folders.json` に記録され、このファイルから消せば許可を取り消せます。許可したフォルダでも、Tower が呼ぶ git では fsmonitor・外部の差分ツール・textconv・通信を使わず、リポジトリの設定に filter があれば git を呼びません。

サイドバーの上の歯車のボタンまたは Ctrl+, で、設定を開きます。配色は Git Bash（mintty）のテーマ（`C:\Program Files\Git\usr\share\mintty\themes`、`~/.mintty/themes`、`~/.config/mintty/themes`、`%APPDATA%\mintty\themes`）から選べ、ターミナルだけでなくサイドバーやファイルの表示もその配色に合わせます。「Git Bash（…）」は `~/.minttyrc` の `ThemeFile` と同じテーマです。「Git Bash に合わせる」を押すと、配色に加えて `~/.minttyrc` のフォント・文字の大きさ・カーソルの形と点滅も合わせます（書かれていない項目は mintty の既定の Lucida Console・9pt・縦線・点滅にします）。ただし透明度・選択したときの色・行の間隔は合わせないので、Git Bash とまったく同じ見た目にはなりません。PC に無いフォントを入れると、その旨を表示します。選ぶとすぐに画面に反映され、「キャンセル」で開く前に戻ります。テーマのファイルを追加したときは、Tower を起動し直すと一覧に出ます。

サイドバーは、上の「<」または Ctrl+Shift+B でたたむと、番号と状態のランプだけの細い帯になります。セッションはドラッグで並べ替えられ（Ctrl+1〜9 の番号も並びに合わせて変わります）、ダブルクリックで名前と印を変えられます（ヘッダーの名前のダブルクリックでも変えられます）。印は「prod」のような短い文字と色で、セッションではなくフォルダに付きます。そのフォルダと中のフォルダで動くセッションすべてのサイドバー・カード・ヘッダーに出るので、本番に関わるフォルダを赤くするなど、似たセッションを見分けるのに使えます。

ヘッダーの「テンプレート」または Ctrl+Shift+T で、よく使う指示を選んでエージェントの入力欄に入れられます。入れるだけで送信はしないので、書き足してから Enter で送ってください。テンプレートは一覧の「テンプレートを編集…」で追加・変更・削除できます。

セッションが無いときの画面の下には、Tower のキャラ（ヘッドセットを付けた管制塔）と滑走路の小さな場面を出します。ときどき飛行機が離陸し、セッションを始める操作をしたときにも離陸します（Windows で動きを減らす設定にしていると動きません）。

一覧画面（サイドバーの「一覧」または Ctrl+0）では、全セッションをカードで並べて表示します。Claude Code と Codex のカードには、セッション画面の「会話」と同じく会話を整えて表示し、下の入力欄から指示を送れます（送れるのは指示待ちのときだけです）。作業中は入力欄の上に、エージェントが画面に出している進み具合の行（`✻ Thinking… (12s · esc to interrupt)` など）を出し、30 秒以上画面が変わらないと「画面の変化なし」と出します。入力欄が空のときに「/」を打つと、コマンドの候補を選べるよう画面の表示に切り替わります（作業が始まるか、カードの外へ移ると戻ります）。入力待ちになったカードは、許可の確認や選択肢に答えられるよう、次に説明する画面の表示に切り替わります。それ以外のエージェントのカードには、エージェントの画面の末尾をターミナルと同じ色で表示します。一覧を開いている間は、各セッションのターミナルの幅をカードの幅に合わせ、エージェントにその幅で画面を描き直させます（折り返すと表や選択肢の並びが崩れるため）。セッション画面に戻ると、ターミナルの幅に戻します。入力中はカーソルと、日本語入力の変換中の文字も出ます。枠の中をスクロールすると直近 300 行（設定の「通知と履歴」で 100〜2000 行に変えられます）までさかのぼれ、さかのぼっている間は表示の更新を止めます（いちばん下に戻すと最新に追いつきます）。画面の末尾の枠をクリックすると、そのセッションにそのままキー入力できます（日本語入力・貼り付け・矢印キー・Esc・Ctrl+C なども送ります）。`/resume` などの選択画面も操作できます。「テンプレート」でテンプレートを入力欄に入れられます（送信はしません）。画面の末尾の枠をダブルクリックするか、カードのそれ以外の場所をクリックすると、そのセッションのターミナルに切り替わります。カードは上の名前の行をつかんでドラッグすると並べ替えられます（サイドバーと同じ並びなので、どちらで並べ替えても両方に反映されます）。

ファイルをターミナル（一覧ではカードでも可）にドラッグして落とすと、そのファイルの場所が入力に入ります。スクリーンショットなどの画像を Ctrl+V で貼り付けると、一時フォルダ（`%TEMP%\tower-images`）に PNG などで保存して、その場所を入れます。どちらも入れるだけで送信はしないので、指示を書き足してから Enter で送ってください。エージェントはその場所からファイルを読みます。

作業が終わったセッションをまだ開いていないときは、サイドバーとカードに「未確認」の印が付きます（一覧の上には件数が出ます）。そのセッションを開くと外れます。

裏のセッションが入力待ちになると、タスクバーのアイコンが点滅し、ウィンドウタイトルに件数が出て、Windows の通知も表示されます。20 秒以上かかった作業が終わったときも通知します（途中で許可の確認を挟んでも、作業の始まりから数えます）。表示中のセッションをウィンドウで見ているときは通知しません。通知をクリックすると、そのセッションに切り替わります（画面に出ている間のクリックのみ。通知センターからのクリックでは切り替わりません）。入力待ちの通知（点滅を含む）と完了の通知は、設定の「通知と履歴」でそれぞれオフにできます。

動いているセッションがあるときにウィンドウを閉じても、Tower は終了せずタスクトレイに隠れ、セッションも通知もそのまま動き続けます（入力待ちの件数はトレイのアイコンにマウスを乗せると出ます）。トレイのアイコンをクリックするとウィンドウが戻ります。終了するときは、トレイのアイコンを右クリックして「終了」を選んでください。動いているセッションが無いときは、ウィンドウを閉じるとそのまま終了します。Tower をもう一度起動したときは、新しく立ち上げずにトレイにいる方を前に出します。トレイにいる間に新しいバージョンをインストールしてから起動すると、再起動するか聞きます（再起動すると動いているセッションは終了するので、「前回の N 件を再開」で開き直してください）。

一度開いたフォルダは「最近開いたフォルダ」として最大 20 件覚えておきます。「新しいセッション」（Ctrl+Shift+N）を押すと、WebStorm のようこそ画面のように、プロジェクト名と薄いパスの一覧が出ます（検索欄で絞り込めます）。クリックか Enter で前回と同じエージェントですぐ開き、Shift を押しながらだとエージェントや worktree を選ぶダイアログで開きます。初めてのフォルダは「参照…」か「新しく作る」から開いてください。セッションが無いときの画面にも同じ一覧が出ます。× で一覧から外せます（フォルダは消しません）。

新しいセッションのダイアログで「新しい worktree で作る」を選ぶと、リポジトリの隣に `リポジトリ名-ブランチ名` のフォルダを `git worktree add` で作り、そこでセッションを起動します。同じリポジトリで複数のエージェントを並列に動かしてもファイルが衝突しません。サイドバー・カード・ヘッダーには各セッションのブランチが出ます（worktree のものは紫）。worktree のセッションでは、元のフォルダを出します（サイドバーとカードは名前の横に `← try-sub`、ヘッダーはブランチの横に `feat-b ← try-sub（main）`。マウスを乗せるとフルパスが出ます）。git はどのブランチから作ったかを残さないので、出すのは元のフォルダの今のブランチ、つまり「取り込んで削除」で取り込む先です。git は呼ばず、`.git` のファイルを読むだけです。worktree で動いていたセッションを閉じると、片付け方を選べます。元のフォルダのブランチに入っていないコミットがあれば「取り込んで削除」（元のフォルダで `git merge` してから worktree とブランチを削除。競合したら取り込みをやめて元に戻します）か「worktree だけ削除」（ブランチは残す）、すべて入っていれば「削除」を選べます。未コミットの変更がある worktree は削除しません。片付けは Git の表示を信頼したフォルダだけで、元のフォルダに未コミットの変更があるときは取り込みません。

アプリを起動したときにセッションが無ければ、前回開いていたセッションを「前回の N 件を再開」でまとめて開き直せます。各エージェントの「直前の会話を再開」で起動し（`claude --continue`、`codex resume --last`、`copilot --continue`、`agy --continue`）、再開する会話が無ければ新しく始めます。

### Codex を初めて使うとき

Codex は新しい hook を承認するまで動かしません。Tower で最初に Codex を起動すると「Hooks need review」と表示されるので、「Trust all and continue」を選んでください（Tower の hook だけが一覧に出ます）。Tower を更新して hook の中身が変わったときも、もう一度表示されます。承認するまで状態は画面の様子からの推測になります。

## 仕組み

- **ターミナル**: Rust の `portable-pty` で ConPTY 経由で `bash.exe --login -i` を起動します。`git-bash.exe` は mintty を開いてしまうため使いません。Git Bash の場所は自動で探しますが、環境変数 `TOWER_BASH` で明示できます。
- **表示**: xterm.js のインスタンスは 1 つだけです。各セッションの出力は Rust 側の仮想端末（`vt100` クレート）に常に流しておき、切り替え時はそのスクロール履歴（既定は 2000 行。設定で 1000〜10000 行に変えられ、変えた値は新しく開いたセッションから使います）と画面を xterm.js に描き直します。裏のセッションの出力はフロントエンドに送らないので、セッション数が増えても UI の負荷は増えません。一覧画面は、開いている間だけ 1 秒ごと（カードに入力している間は 0.15 秒ごと）に、前回から画面が変わったセッションだけスクロール履歴を含めて、設定の行数分の直近の出力を取得します（`peek_sessions`）。
- **状態表示（hooks）**: 各エージェントの hooks が `curl` でアプリにイベントを送り、アプリがサイドバーの状態に反映します。受信口は起動のたびに空いているポートで開き、ポート番号とランダムなトークンをセッションの環境変数（`DASH_HOOK_PORT` / `DASH_HOOK_TOKEN`）で渡します。トークンの無いリクエストやブラウザからのリクエストは受け付けません。hook の入力のうち送るのは Claude Code と Copilot CLI の通知（入力待ち）の内容と、Claude Code と Codex の SessionStart（セッション ID と会話の記録ファイルの場所など）だけで、実行するコマンドやファイルの内容は送りません。hooks の設定ファイルにはポートもトークンも書かないので、Tower の外で起動したエージェントでは何もしません。
  - **Claude Code**: `claude --settings <hooks設定>` で起動します。設定は `%APPDATA%\dev.tower.app\hooks-settings.json` に書き出すもので、`~/.claude/settings.json` は変更しません。
  - **Codex**: `codex -p tower` で起動し、`~/.codex/tower.config.toml`（プロファイル）を利用者の設定の上に重ねます。Codex はこのファイルにフォルダの信頼などを書き足すので、Tower は `[[hooks.…]]` のテーブルだけを更新し、それ以外は残します。
  - **Copilot CLI**: `~/.copilot/hooks/tower.json` を置きます。
  - Codex と Copilot CLI のファイルは、それぞれの設定フォルダ（`~/.codex`、`~/.copilot`）があるときだけ Tower の起動時に書き出し、既存の設定ファイルは変更しません。
- **状態表示（画面からの推測）**: hooks を使えない Antigravity CLI と、hooks のイベントがまだ届いていないセッションは、画面の変化と内容から状態を推測します。画面が動いていれば作業中、3 秒止まれば完了、画面の下のほうに承認を求める文言（「Do you want to」「1. Yes」など）があれば入力待ちとみなします。
- **プロセス管理**: 各セッションの bash.exe を Windows の Job Object に入れています。セッションを閉じたとき（またはアプリを終了したとき）、エージェントや MCP サーバーを含む子孫プロセスがまとめて終了します。
- **メモリ表示**: 2.5 秒ごとに bash.exe 以下のプロセスツリーのメモリを合計して表示します。

## 現時点の制限

- セッションを切り替えて戻ったときに復元するスクロール履歴は、設定の行数（既定は 2000 行）までです。ウィンドウの幅を変えた後に戻ると、幅を変える前の行は右端で切れたり折り返したりします。
- トレイの「終了」で Tower を終了すると、全セッションが終了します（Job Object の仕様）。PC の再起動やサインアウトでも終了します。次回の起動時に「前回の N 件を再開」で開き直せます。
- Antigravity CLI の状態は推測なので、入力待ち・完了の判定は目安です。
- WSL 上のエージェントには対応していません。

## うまく動かないとき

- **状態が変わらない・おかしい**: サイドバー下部にエラーが出ていないか確認してください。Git Bash で `curl` が使えるかも確認してください。
  - Codex: 「Hooks need review」で信頼を承認したか確認してください（`/hooks` でも確認できます）。
  - Copilot CLI: `copilot --version` が 1.0 以降か確認してください。古い場合は `npm i -g @github/copilot` で更新します。
- **bash が起動しない**: 環境変数 `TOWER_BASH` に `C:\Program Files\Git\bin\bash.exe` のようなフルパスを設定してください。
- **日本語が豆腐になる**: ターミナルのフォントは、設定で選んだもの → Cascadia Code → BIZ UDGothic → Consolas の順で使います。選んだフォントに日本語が無ければ BIZ UDGothic で表示します。

